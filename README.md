# Анализ личности: расчёты Python и HTML-отчёт

Скрипты считают показатели Human Design, гематрии, нумерологии, астрологии и авторского опроса архетипов.

Агент объясняет результаты и собирает два синтезных раздела: карту предназначения и финансовый потенциал.

Исходные данные открыты в начале страницы, после восьми подробных глав идёт общий разбор с портретом, сильными сторонами, возможными напряжениями и приоритетными действиями.

Вывод — страница для сайта (папка `index.html` + `assets/` и zip-архив) или один автономный HTML-файл. На странице анимированные сцены: бодиграф, расчёт гематрии по буквам, ключевые числа, квадрат нумерологии, круг планет с осями, пики и вызовы, профиль архетипов.

## Быстрый запуск

Требуются Python 3.9+ с базой часовых поясов IANA и полная копия репозитория.

```sh
python3 -m venv .venv
.venv/bin/python -m pip install -r requirements.txt
mkdir -p runs/demo
.venv/bin/python personality.py calculate --input examples/input.json --output runs/demo/calculation.json
.venv/bin/python personality.py check --calculation runs/demo/calculation.json
.venv/bin/python personality.py render --calculation runs/demo/calculation.json --site runs/demo/site
```

Это расчётный черновик, без выдуманной интерпретации.

[Полный демонстрационный HTML](examples/report.html) содержит только вымышленные данные и синтетические ответы.

Чтобы воспроизвести его из закреплённых файлов:

```sh
.venv/bin/python personality.py render --calculation examples/calculation.json --narrative examples/narrative.json --output runs/demo/report.html
```

Открой файл в браузере; он не требует сервера или подключения к сети.

Пример показывает форму результата и осторожное объяснение показателей, а не разбор реального человека.

## Работа с агентом

Начни с [personality.md](personality.md) или навыка [.agents/skills/personality-loop](.agents/skills/personality-loop/SKILL.md).

Полный порядок и критерии готовности — в [workflow.md](workflow.md), поля JSON и интерфейсы — в [docs/input.md](docs/input.md).

Первоначальный текст пишет [автор инфостиля](roles/infostyle-writer.md) по нашей готовой методичке promt-copywriting; затем отдельный [редактор социальных поглаживаний](roles/supportive-editor.md) добавляет теплоту и поддержку, сохраняя расчёты, источники и границы интерпретаций.

Подготовка закреплённой зависимости описана в [copywriting-integration.md](docs/copywriting-integration.md).

```sh
.venv/bin/python personality.py infostyle --list
.venv/bin/python personality.py infostyle --cards 1.9,12.2,14.5
```

Команда выдаёт целые выбранные карточки; вторую копию инфостиля, голос Романа и гусарский регистр этот проект не создаёт.

Для собственного разбора положи подтверждённые данные в `runs/<задача>/input.json` по образцу.

Затем:

```sh
.venv/bin/python personality.py questionnaire
.venv/bin/python personality.py summary --calculation runs/demo/calculation.json
```

`questionnaire` выдаёт 36 утверждений без ключа; `summary` передаёт автору интерпретаций сводные факты и ограничения вместо исходников расчётного ядра.

Интерпретация хранится отдельно в narrative.json, с calculation_id и ссылками на ID фактов.

После её подготовки:

```sh
.venv/bin/python personality.py check --calculation runs/demo/calculation.json --narrative runs/demo/narrative.json
.venv/bin/python personality.py render --calculation runs/demo/calculation.json --narrative runs/demo/narrative.json --site runs/demo/site
# или один файл: --output runs/demo/report.html
```

Нельзя просто перенести готовую интерпретацию на другой расчёт: проверка отклонит чужой идентификатор или отсутствующий источник.

`check` проверяет структуру и связи; смысл выводов и понятность текста проходят отдельное ревью.

Правка текста не требует повторять опрос и вычислять карту; изменение исходных данных или метода требует нового расчёта и проверки зависимых выводов.

## Расчётные правила

| Модуль | Где закреплён алгоритм |
|---|---|
| Буквы, числа, циклы и опрос | [Арифметика v1](docs/arithmetic.md) |
| Положения тел, HD, временные зоны и ограничения | [Эфемериды](docs/ephemeris.md) |
| Понятный язык и границы синтеза | [Интерпретация](references/interpretation.md) |
| Изменения и проверка миграции | [Миграция](docs/migration.md) |

Astronomy Engine 2.1.19 используется по умолчанию; прежний приближённый backend доступен только явным выбором legacy, без автоматической подмены.

Узлы и ASC/MC остаются приближёнными и явно обозначаются в результате; на круге оси подписаны «Асц≈» и «MC≈».

Неизвестное время не заменяется полуднем; недоступные модули показывают причину отсутствия.

Совпадение временных выборок не является доказательством устойчивости всей карты внутри окна.

Точные арифметические операции не подтверждают научную истинность интерпретаций этих систем.

## Формат и приватность

По выбору автора здесь отдельная [дизайн-система](docs/design-system.md) для аудитории, интересующейся астрологией: мягкая мистика, молочный фон, сливовый и пыльная роза.

Выразительные заголовки с засечками сочетаются с простым шрифтом основного текста; используются локальные системные шрифты без внешних запросов.

Есть переключатель тёмной и светлой темы (по умолчанию тёмная), доступные с клавиатуры блоки и таблицы и стили для печати. Анимации сцен работают через небольшой локальный scenes.js; без него, при «уменьшить движение» и в печати видна полностью нарисованная графика.

На странице стоит noindex, но это не контроль доступа и не пароль.

Персональные данные и готовые отчёты держи в игнорируемом `runs/` или вне репозитория; публикация на сайте выполняется отдельным действием.

## Проверка разработки

```sh
.venv/bin/python -m unittest discover -s tests -v
git diff --check
```

Расчётный код проверяется граничными случаями и независимыми астрономическими примерами, HTML — также в браузере на 375 и 1280 px.
