# Подключение готового инфостиля

Проект использует исходную методичку из [promt-copywriting](https://github.com/BermanRoman/promt-copywriting), а не её переписанную версию.

В [dependencies.json](../dependencies.json) закреплены источник, файл `methodology-copywriting.md`, ревизия `bb091b6003f836106d09ed2bd5e91a8fb5d961dd` и SHA-256 содержимого.

Копия методички в этом репозитории не хранится.

## Подготовка зависимости

Если локального clone ещё нет, подготовьте его отдельно в соседнем каталоге:

```sh
cd ..
git clone https://github.com/BermanRoman/promt-copywriting.git promt-copywriting
git -C promt-copywriting checkout --detach bb091b6003f836106d09ed2bd5e91a8fb5d961dd
cd promt-personality
```

Перед checkout существующего clone сохраните его незавершённые изменения; CLI не переключает ревизии и не скачивает зависимость автоматически.

По умолчанию используется соседний `../promt-copywriting` относительно расположения проекта, независимо от текущего рабочего каталога.

Для другого расположения передайте `--root` с точным корнем локального репозитория.

CLI проверяет, что Git-корень совпадает с указанным каталогом, HEAD равен закреплённой ревизии, исходный файл находится внутри этого корня и его SHA-256 точно совпадает с манифестом.

Изменение нужного файла, другая ревизия, неверный корень или неизвестная карточка завершают команду кодом 2 и пояснением в stderr; stdout при ошибке остаётся пустым.

Обновление зависимости — отдельное согласованное изменение манифеста с проверкой совместимости, а не автоматический переход на свежую ветку.

## Адресная выборка

```sh
.venv/bin/python personality.py infostyle --list
.venv/bin/python personality.py infostyle --cards 1.9,12.2,14.5
.venv/bin/python personality.py infostyle --root /path/to/promt-copywriting --cards 2.1,3.6
```

`--list` выводит только индекс заголовков карточек уровня `##`.

`--cards` выводит целые выбранные карточки в запрошенном порядке, включая условия применения и критерии проверки; посторонние блоки и вступление не добавляются.

Выбор всех нужных карточек выполняется до записи в stdout, поэтому неизвестный номер не оставляет частичного успешного результата.

Весь инфостиль доступен через индекс и адресную выборку; для разбора текста обычно нужны блоки 1–7 и 12–14, остальные подключаются по условиям задачи.

Номера выбираются по реальной проблеме текста: например, непонятный термин, перегруженный абзац или слабый переход, а не ради формального прохождения всех карточек.

Интеграция не загружает голос автора, Гусара, правила восприятия на слух и полный workflow копирайтинга.

## Применение к отчёту

Сначала сохранить расчёт, источники и ограничения, затем выбрать подходящие карточки для объяснения этих данных понятным письменным языком.

Редактура не меняет числа и не превращает символическую интерпретацию в установленный факт.

Карточка 1.7 о неуверенности и модальности не даёт права убирать обоснованные оговорки, превращать гипотезу в факт или обещать прогноз.

Если вывод не подтверждён исходными данными, его нужно ограничить или пересмотреть, а не усиливать категоричность формулировки.

После правки заново проверить ссылки на факты и соответствие интерпретации расчёту; сама выборка карточек не является проверкой смысла отчёта.

## Проверка интеграции

```sh
.venv/bin/python -m unittest discover -s tests -p test_infostyle.py -v
```

Тесты создают временные локальные Git-репозитории с синтетическими карточками и проверяют целостность выборки, неизвестные номера, изменение файла, неверную ревизию и неверный корень.

Реальный CLI-прогон дополнительно проверяет закреплённый clone; он не требует загрузки всей методички в контекст редактора.
